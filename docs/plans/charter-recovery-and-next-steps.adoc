== Executive sequencing decision

Finish the native governance artifact seam, then *recover the existing gates*.
Do not proceed directly to more Raft, a polyrepo split, package registration, or
new protocol promises. The present source is a useful prototype estate, not a
proven production framework. The next milestone should be a reproducible, governed,
real HTTP relationship-explorer slice with actual persistence, then standards
interop and browser evidence.

Critical path:

....
Evidence/CI repair -> IR + Codec correctness -> real HTTP Core
                      |                         |
                      +-> native gateway fixes -+-> governed unary E2E
                      |                         |
                      +-> real storage ---------+-> relationship explorer
                      +-> adapter interop ------+-> real browser acceptance
                                                    |
                                               release review
                                                    |
                                          optional Control/Live/CRDT
                                                    |
                                    conditional Raft; gated HTTP/2
....

Gateway fixes can run in parallel with the IR/Core work, but all must converge
before an externally exposed deployment. Security implementation is not deferred
merely because the human security-review phase is numbered later.

== Work package C: make the launch seams real (Gates 1–3 / charter Phases 1–2)

Dependencies: B's toolchain decisions; use maintained HTTP/JSON libraries.

=== C1: IR and schema artifacts

* Complete validation for field TypeRefs, primitives, maps/optionals/lists, names,
  duplicate semantic routes and reserved bindings; implement or unexport `from_dict`.
* Preserve one descriptor as the source of routes and OpenAPI, GraphQL, proto,
  capability policy and contract fingerprints. Do not extract policy from a separate
  handwritten route table or let application routes drift from descriptors.
* Correct OpenAPI path merging, escaping, colon-to-brace parameters and JSON Schema
  components; validate generated specs independently. Define large integer, bytes,
  timestamp, nullable/omitted/default semantics per brief §4.
* Compile emitted `.proto` with a pinned standard compiler; support primitives via
  valid message/wrapper rules and deterministic field numbering/evolution decisions.
* Wire the existing proto/OpenAPI/GraphQL CLI stubs to actual emitters and implement
  or remove the advertised `routes` command. Do not report comment output as codegen.

Exit: descriptor freeze only after independent validators and positive/negative
golden tests; generated artifact drift CI; explicit compatibility/versioning policy.

=== C2: Codec, router and transport

* Replace `codeunits(string(obj))` with JSON3-backed wire encoding and decoding;
  implement q-values, q=0 exclusion, wildcard specificity, unsupported Accept,
  media parameters and `Vary`. Keep MsgPack/CBOR native dependencies optional.
* Add the HTTP.jl adapter over streaming-symmetric handlers, request-scoped context,
  middleware and error mapping. Define route registration from IR, not parallel code.
* Fix root routing and nested parameter capture; encapsulate mutable trie internals
  so “immutable snapshot” is enforceable. Benchmark route allocations rather than
  repeating the zero-allocation docstring. Never add a DB/control lookup to routing.
* Make cancellation interrupt blocked producers/consumers, bound bodies/queues,
  handle client disconnect, enforce monotonic deadlines and redact internal errors.
* Implement and test startup/readiness/draining/SIGTERM behavior on a real socket.
  Trace IDs must interoperate with W3C Trace Context rather than just use random UUIDs.

Exit: real client -> IR-driven HTTP endpoint -> native JSON round trip, not direct
Julia dispatch; negative HTTP tests; cold-start/first-response, warm p50/p95/p99,
allocations, slow-consumer and repeated-connect memory baselines with commands/hardware.
Owners: IR/schema maintainer and Core/Transport maintainer, reviewed together.

== Work package D: strict gateway and real sidecar acceptance

Dependencies: A + C2. Gateway maintainer owns upstream fixes; do not silently fork
its security model inside MaridIR. The follow-up authorizes local paired changes;
upstream merge, deployment and release acceptance remain separate decisions.

. Define a deny-by-default DSL behavior: permit empty globals or an explicit
  default-deny policy, and distinguish “no path matched” from “path matched but
  verb forbidden.” Test that a global rule cannot undo a route denial.
. Establish deterministic precedence for exact/parameter/regex routes; reject
  ambiguous patterns at compile time. Only then consider relaxing Marid's overlap
  rejection. Test shared-path method-specific capability semantics if added.
. Publish policy revisions atomically as a table pair or one immutable handle;
  preserve readers of old revisions until safe retirement. Race-test reload failures,
  including malformed policy and concurrent requests.
. Repair the production Containerfile/config sequencing; build a pinned non-root
  image. Exercise real runtime policy loading, not merely `PolicyValidator.validate`.
. Harden the proxy against Req header/body representation mismatches, oversized or
  chunked bodies, redirects/SSRF, upstream timeouts, spoofed identity and hop-by-hop
  header handling. Management endpoints must have an explicit external exposure policy.
. Run the Compose stack with real Marid HTTP service and no backend host port.
  Record allowed and denied decisions plus backend hit counters. Test unknown paths,
  HEAD/OPTIONS/TRACE/CONNECT, encoded slash/dot paths, regex injection near-misses,
  auth downgrade/spoofing, absent/invalid policy, backend outage and restart rollback.
. Measure unary-path latency/memory, check request-ID propagation and sensitive log
  redaction, and review TLS/mTLS ingress. Keep SSE/WS/gRPC outside the supported
  matrix until separately proven across the proxy; no undocumented bypass path.

Exit: reviewer-approved threat model + passing real HTTP/container failure matrix,
no exposure bypass, measured overhead and verified rollback. Only after this may
“wired and evaluated governance sidecar” mean production data-path acceptance.

== Work package F: prove standard clients and actual browsers (Gates 1, 3, 4)

Dependencies: C; reference dataset from E; D for any claimed sidecar support.

* GraphQL: adopt maintained parsing/validation machinery, valid input/output SDL
  and full introspection; then resolvers, variables, mutations, partial errors,
  depth/complexity limits and a named SSE/WS subscription transport. Use independent
  GraphQL clients; string matching `__schema` is not protocol support.
* JSON-RPC: test notifications (no response), batches, invalid JSON/requests,
  positional/named params, ID preservation and sanitized errors through HTTP.
  MCP: select/pin the protocol version, initialize/negotiate, tools/resources,
  transport/session semantics and cancellation with an independent MCP client.
* Cap'n Proto/Bebop: bidirectional golden fixtures with independent implementations,
  endian/boundary/malformed-input tests and pinned schema/compiler/runtime notices.
  Require explicit approval if this turns into a new runtime/compiler project.
* Browser: prove AffineScript compilation or approved fallback; run Chromium,
  Firefox and WebKit against the real service. Exercise bare client, real React,
  real Vue and the shared Custom Element—not hook or DOM shims alone.
* Test already-aborted signals, SSR-safe import, request-scoped credentials/caches,
  actual unmount cleanup, reconnect after clean EOF and failure, sequence gaps,
  snapshot resynchronization, credential/CORS policy and old-client/new-server rollout.
* Measure real analysis progress, cancellation, repeated reconnect memory and
  cross-protocol semantic equivalence from the one application service.

Exit: published exact support matrix, native client logs and real-browser reports;
unsupported stream modes explicit. Owners: adapter and frontend maintainers.

== Work package H: late distributed features and Phase 8

Do not let existing prototype packages bypass charter gates.

* Phase 6 CRDT: property-based convergence, idempotence/commutativity/associativity,
  causal/tombstone semantics, clock assumptions, restart persistence, presence expiry
  and a reproducible partition simulator. No arbitrary Julia object replication.
* Phase 7 Raft: first demonstrate that etcd is insufficient. Obtain owner approval
  of the Jepsen-style testing budget and an explicit need for owned consensus.
  Until then, keep MaridRaft experimental/non-production and out of default assembly.
  If authorized: durable state, elections, conflicting logs, compaction, membership,
  partitions, crashes and linearizability must be covered before shipping.
* Phase 8 gRPC: choose an audited HTTP/2 binding or explicitly scope to gRPC-Web.
  Passing frame/unframe tests is not a server. Require HTTP/2 conformance and a
  standard gRPC client for every advertised unary/server/client/bidi mode, including
  deadlines, trailers, flow control, cancellation and compression/error handling.
  Gate browser translation independently and never label custom WS binary RPC gRPC.
* Extend artifacts later with AsyncAPI 3.x, CloudEvents and client codegen from IR,
  after standards versioning and event lifecycle contracts are proven.

Exit: feature-specific evidence, not bundled assertions of “Phase 8 complete.”
No own Raft, native DBMS, crypto, visual builder, Genie API cloning, Julia SSR or
Cap'n Proto RPC is added by this plan.

== Management and evaluation cadence

Use issue-sized tasks with one owner, dependency IDs, touched contracts, exact
commands, expected outputs and an exit decision. The reconstruction findings in
`docs/audits/recon-2026-09-19.adoc` are proposed issue seeds, not fabricated GitHub
issues. Open them only with authorization.

At each checkpoint report: implemented; tested with exact runtime/source versions;
not tested/skipped; blocked; accepted by whom. Archive logs with commit and policy
hashes. No blanket percentage or “fully verified” language without coverage of brief §8.

Suggested next bounded assignment: B's CI/evidence ledger plus C1/C2's smallest
real IR-to-HTTP JSON endpoint, in parallel with upstream D1's fallback semantics.
Do not estimate a release date until those spikes expose the remaining runtime work.
