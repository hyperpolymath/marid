= Feasibility Audit: Gate 0
:toc:
:sectnums:

[abstract]
Gate 0 evidence-backed feasibility evaluation for the Marid program (`PROJECT_BRIEF.md` §9).
Audited on 2026-09-19 against Julia General Registry, upstream repositories, and official
runtime specifications. Every claim distinguishes between pure Julia implementations,
external runtime adapters, missing capabilities, and project blockers.

== Executive Summary

The Marid framework commitments require native protocol interoperability, a pure local
routing data plane, an IR-first design, and standalone integration packages. This audit
verifies the viability of Julia packages and external runtimes for ArangoDB, gRPC/HTTP/2,
GraphQL, Cap'n Proto, Bebop, and the AffineScript/Bun browser environment.

The core conclusion: **Phase 1–3 deliverables are highly feasible with focused, bounded implementation work in Julia**. High-risk runtime engineering (such as implementing a custom HTTP/2 multiplexing server in Julia) is successfully avoided by adhering to the Phase 8 deferral of native gRPC in favor of libnghttp2 bindings / gRPC-Web, and scoping Cap'n Proto and Bebop as serialization codecs within `MaridCodec`.

== Detailed Component Feasibility

=== 1. ArangoDB HTTP Client (`ArangoDB.jl`)
* **Status**: Clean-room implementation required; no conflicting packages exist in the Julia General Registry.
* **Architecture**: Standalone package (`packages/ArangoDB/`) with zero dependencies on `MaridCore`.
* **Transport & Serialization**: Uses `HTTP.jl` connection pools and `JSON3.jl` zero-allocation JSON parsing.
* **Required Endpoints**:
  - `POST /_api/cursor`: AQL query execution, batch sizing, cursor continuation, and cleanup.
  - `POST /_api/document/{collection}`: Document creation with `returnNew` and `overwriteMode`.
  - `GET /_api/document/{collection}/{key}`: Document retrieval with `If-Match` / `_rev` validation.
  - `PUT /_api/document/{collection}/{key}`: Revision-aware updates.
  - `POST /_api/transaction`: Multi-document ACID transactions with stream IDs.
* **Test Database Target**: Official Docker container `arangodb:3.12` (Community Edition). Test suites will verify cursor timeout cleanup, conflict error codes (`1200 ERROR_ARANGO_CONFLICT`), and retry policies.

=== 2. gRPC and HTTP/2 Strategy
* **Status**: Native pure-Julia gRPC is deferred to Phase 8 per framework charter alignment.
* **Ecosystem Reality**: `HTTP.jl` remains an HTTP/1.1 engine. `PureHTTP2.jl` lacks production stress-testing, session flow-control windowing, and frame interleaving. `Nghttp2Wrapper.jl` wraps the battle-tested C library `libnghttp2`.
* **Decision**: 
  - Phase 1–3 will deploy **`MaridRPC.jl`** (JSON-RPC 2.0 and Anthropic Model Context Protocol [MCP] over HTTP/SSE), providing high-value RPC interoperability without HTTP/2 complexity.
  - Phase 8 will introduce native gRPC via `Nghttp2Wrapper` FFI or Connect protocol over HTTP/1.1.

=== 3. GraphQL SDL & Execution (`MaridGraphQL.jl`)
* **Status**: Hybrid approach.
* **Phase 1 Scope**:
  1. **IR-to-SDL Emitter**: Pure Julia function mapping `MaridIR.ServiceDescriptor` to canonical GraphQL SDL schema text.
  2. **Introspection Engine**: Responds to standard `__schema` and `__type` queries.
  3. **Execution Runtime**: Resolver pipeline mapping GraphQL AST queries to Julia domain services, passing `CallContext` and resolving partial errors according to the GraphQL June 2018 specification.
* **Upstream Dependencies**: `GraphQLite.jl` for AST parsing and schema validation rules.

=== 4. Cap'n Proto and Bebop Serialization
* **Status**: Codec extensions, not standalone RPC engines.
* **Cap'n Proto**: Handled via `OndrejSlamecka/Capnp.jl` or a dedicated pointer-arithmetic `ByteBuf` unpacker in `MaridCodec.jl`. RPC capability pipelining is confirmed as a non-goal.
* **Bebop**: Wire specification is compact little-endian records with byte-length prefixes. `MaridCodec` will implement direct buffer read/write methods generated from `MaridIR`.

=== 5. Browser Client and Runtime
* **Runtime**: Bun (pinned via `mise.toml`). Node/npm/pnpm/yarn and Deno remain ejected.
* **Language**: AffineScript (JaffaScript face, compiling to typed WebAssembly).
* **Architecture**: The core SDK (`@marid/client`) exposes standard Web APIs (`Promise`, `AbortSignal`, `AsyncIterable`). Plain JavaScript facades provide ergonomic bindings for `@marid/react` and `@marid/vue`.

== Gate 0 Recommendation
**PROCEED TO GATE 1 SPIKES.** No unmanageable external runtimes or proprietary protocols are required. All Phase 1–3 packages can be implemented in native Julia and AffineScript under standard open licenses.
