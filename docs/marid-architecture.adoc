= Marid Architecture Specification
:toc:
:sectnums:

[abstract]
Architectural specification for the Marid framework (`PROJECT_BRIEF.md` §3–§4;
`docs/MARID-FRAMEWORK.adoc`). Reconciled and approved at Gate 0. Defines package
boundaries, the control/data plane split, core compatibility contracts, and the
exact execution pipeline.

== Architecture Overview

Marid is engineered as a clean-room, package-first framework structured into four
orthogonal layers:
1. **Intermediate Representation (IR)**: Pure service, method, and streaming descriptions.
2. **Protocol Adapters & Codecs**: Standalone modules translating native protocols to/from the IR.
3. **Core Data Plane**: Pure trie routing, streaming middleware pipeline, and `CallContext`.
4. **Pluggable Persistence**: Abstract storage seam backed by ArangoDB for production graph/document workflows.

   └──────────┬────────────┘
              │

== The 12 Architectural Principles & Invariants

1. **Control Plane / Data Plane Split**:
   - Route lookup is a deterministic, pure function over an immutable, locally cached snapshot.
   - It never blocks, never allocates dynamic locks, and never touches the network.
   - Consensus and configuration distribution live exclusively in the control plane (`MaridControl`).
   - Nodes continue serving traffic with full fidelity even if the control plane is unreachable.
2. **IR-First Contract Generation**:
   - `MaridIR` is the single source of truth for all service definitions.
   - OpenAPI 3.1, JSON Schema 2020-12, GraphQL SDL, and Protobuf/Bebop definitions are emitted directly from the IR.
   - Zero schemas are maintained by hand in parallel.
3. **Seams Before Features**:
   - Bounded streaming handlers (`Stream{I} -> Stream{O}`), the Transport seam (`MaridTransport`), the Codec seam (`MaridCodec`), and `CallContext` are implemented before any specific protocol adapter.
4. **No In-Tree DBMS Engine**:
   - Marid does not implement a database engine. Storage is pluggable via `MaridStorage`.
   - `ArangoDB.jl` is an independent, native Julia HTTP client exposing graph, edge, document, and AQL capabilities directly without an ORM abstraction.
5. **Small, Independent Packages**:
   - Each package lives in its own subdirectory under `packages/` with its own `Project.toml`.
   - Standalone adapters (`ArangoDB.jl`, `MaridCodec.jl`, `MaridRPC.jl`) are fully usable without loading `MaridCore`.
6. **Standards Over Custom Integrations**:
   - APIs emit standard OpenAPI 3.1, RFC 9457 Problem Details, GraphQL SDL, and W3C TraceContext headers.
   - Frontend SSR (Next.js/Nuxt) is supported via documented sidecar proxy patterns, never reimplemented in Julia.
7. **First-Class HTML Fragments**:
   - Server-sent reactive UI updates (HTMX, Turbo, Datastar) are supported natively in `MaridLive` over SSE and WebSockets.
8. **Security from Audited Libraries**:
   - No custom cryptographic implementations, bespoke hashing, or hand-rolled session cookies.
   - Relies on OpenSSL/crypto primitives and standard bearer-token verification.
9. **Zero Metaprogramming Over The Wire**:
   - Arbitrary Julia `eval`, `Meta.parse`, or unsafe object deserialization from untrusted incoming network messages is strictly prohibited.
10. **Documentation as a CC-BY-SA-4.0 Deliverable**:
    - Prose documentation is treated as a tested deliverable maintained in AsciiDoc.
11. **Strict Contribution Hygiene**:
    - All commits require Developer Certificate of Origin (DCO) sign-off and SPDX license headers.
12. **Boring Correctness for Consensus**:
    - Distributed state and Raft/CRDTs arrive late, small, and heavily tested, or not at all (`MaridControl` / `MaridRaft`).

== The Six Core Contracts

[cols="1,3",options="header"]
|===
| Contract | Normative Technical Design

| **Execution Context (`CallContext`)**
| Immutable request-scoped record carrying:
  - `principal`: Verified identity token / subject.
  - `tenant_scope`: Isolated multi-tenant identifier.
  - `deadline`: Absolute monotonic deadline (`time_ns()`).
  - `cancellation`: Cooperative cancellation signal (`Base.Event`).
  - `trace_id`: Distributed trace and span IDs (W3C TraceContext).
  No global singleton holds user or tenant state.

| **Service Interfaces**
| Pure Julia functions operating on typed input streams and returning typed output streams:
  `handler(ctx::CallContext, input::Stream{I})::Stream{O}`
  Handlers have zero awareness of underlying transport protocols (HTTP, WS, gRPC).

| **Streaming & Flow Control**
| Bounded buffering (`Channel{T}(capacity)`). Slow consumers receive backpressure. Client disconnects immediately trigger `notify(ctx.cancellation)` to reclaim backend resources.

| **Domain Errors**
| Stable domain exceptions extending `MaridError`. Protocol adapters translate domain errors deterministically:
  - HTTP: RFC 9457 Problem Details (`{type, title, status, detail, instance}`).
  - GraphQL: `errors` array with path and extensions.
  - gRPC: Canonical status codes and trailers.

| **Data Ownership**
| Decoded request values are owned by the handler. Borrowed buffer slices must be copied if accessed asynchronously beyond the handler lifecycle.

| **Persistence & Transactions**
| Explicit cursor ownership and lifecycle management. Concurrency enforced via document revision checks (`_rev`). Retries are permitted only on demonstrably idempotent read operations.
|===
