= Marid roadmap

The Marid execution plan: six gates from feasibility audit to release
review (`PROJECT_BRIEF.md` §9).

Status: Gate 0 stub. Gate 0 breaks implementation into small, reviewable
issues (goal, scope and non-goals, dependencies, acceptance tests, affected
files/packages, blockers); those issues become this roadmap's working
content. Until then, the brief's §9 is authoritative.

== The gates (summary)

* *Gate 0 — Feasibility and licensing audit.* Inspect the Julia ecosystem
  and native runtimes; verify versions, features, licenses, generated-code
  terms; select the ArangoDB test release; check package names. Produce the
  evidence-backed matrix and stop for approval before any new runtime,
  substantial generator, or non-Julia bridge.
* *Gate 1 — Interoperability spikes.* Disposable, minimal proofs: standard
  gRPC client, Cap'n Proto and Bebop bidirectional interop, standard
  GraphQL client, Julia client against real ArangoDB. Do not freeze the
  shared API until these results are understood.
* *Gate 2 — Foundation.* Package skeletons and independent environments,
  license mapping, CI and test tooling, shared context and lifecycle
  contracts, ADRs, browser-event contract.
* *Gate 3 — Independent packages.* Implement the charter packages
  (Phases 1–3 first, then 4–8 per the roadmap gates) against their
  acceptance criteria; parallel work once contracts and runtime choices
  are approved.
* *Gate 4 — Assembly and browser integrations.* Thin Marid bindings,
  framework-independent client, React/Vue wrappers, reference application,
  real-browser and cross-protocol tests.
* *Gate 5 — Release review.* Support matrix, security and failure behavior,
  licensing, documentation, reproducibility, package registration and
  release order. Public registration, publishing, deployment, and paid
  services require explicit approval.

== Gate → phase mapping

The gates are acceptance checkpoints; the charter phases
(`docs/MARID-FRAMEWORK.adoc` roadmap) are build order. Gate 0 covers
Phase 0 plus feasibility for all phases; Gate 1 de-risks Phases 1–3
entry; Gate 2 sets up Phases 1–2; Gate 3 implements Phases 1–3, then
4–8 per the roadmap gates; Gate 4 assembles plus the Phase 5 frontend;
Gate 5 reviews the whole program. Full table: `PROJECT_BRIEF.md` §9.
