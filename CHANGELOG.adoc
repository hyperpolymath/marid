=== [Unreleased]

==== Added

* Native `http-capability-gateway` Verb Governance Spec (DSL v1 YAML) generator (`emit_capability_spec`) in `MaridIR.jl` ensuring zero contract drift between Marid services and perimeter verb governance.
* CLI support in `scripts/marid generate capability-spec <path>
  (--global-verbs GET[,POST] | --deny-by-default) [--out FILE]` and `scripts/marid
  routes <path>`. The exposure policy must be named: the CLI refuses to emit a spec
  whose global verbs were guessed, because global verbs are public on every path.
* Benchmark suite for IR generation and emitters in `benches/marid_bench.sh`, wired into `just bench`.
* Wired `just test` recipe to run estate verification across all 13 Julia packages.
* Fixed aspect test pattern filtering for documentation and header comments in `tests/aspect_tests.sh`.
* SHA-pinned GitHub Action references in `.github/workflows/julia-ci.yml` and added CLI emitter verification job.
* Added `docs/deployment/docker-compose.adoc` specifying production deployment with Podman Pods, Podman Compose, and the `http-capability-gateway` sidecar architecture.
* Wired `http-capability-gateway` into `build/container/compose.yaml` with fixture policy mounting and healthchecks, verified with `podman compose config` via `just container-verify`.
* Cross-referenced capability governance and Podman container architecture in `docs/deployment/PRODUCTION-GUIDE.adoc`.

* Repository minted from `hyperpolymath/rsr-template-repo` via
  `just repo-init julia-library` (2026-09-18); clade `dx` (Developer
  Ecosystem, secondary `pt`), lineage `monorepo`, preset `julia-library`.
* `PROJECT_BRIEF.md` — the canonical Marid product/engineering contract
  (§1–§9), transcribed from the owner's program brief.
* `AGENTS.md` — repository instructions for coding agents, plus the
  Marid-on-RSR file-mapping notes.
* `THIRD_PARTY_NOTICES.md` and `REUSE.toml` (starter license mapping;
  Gate 2 owns the full mapping).
* Monorepo skeleton: `packages/` (Marid core + five integrations), `web/`
  (client, React, Vue, elements), `contracts/`, `fixtures/`,
  `examples/relationship_explorer/`, `test/interop/` — READMEs only, no
  implementation (Gate 0 not yet started).
* `docs/marid-architecture.adoc`, `docs/marid-compatibility.adoc`,
  `docs/marid-roadmap.adoc` (Gate 0 stubs), `docs/audits/`,
  `docs/adr/`, and `docs/agent-launch.adoc` (Gate 0 kickoff and
  bounded-task prompts).
* `.machine_readable/descriptiles/marid_chora.deed` — the six
  descriptiles (CLADE, META, ECOSYSTEM, AGENTIC, NEUROSYM, PLAYBOOK)
  translated to a `repo-deed` with the standards#837 campaign

==== Fixed

* `scripts/marid generate capability-spec ... --out FILE` piped the emitter through
  `tee`, which opens and truncates the target *before* the generator runs, so a
  rejected service file left an empty policy where a working one had been. `--out`
  now writes to a temporary file in the target's directory and renames only on
  success, and `test/interop/capability_cli.sh` fails if a live policy is ever
  truncated or a stray temporary file is left behind.
* `build/container/compose.yaml` mounted the strict fixture while pulling the
  mutable `ghcr.io/...:latest` gateway image, so the documented quickstart could not
  start against an image predating the #112 correction. It mounts the legacy golden
  `fixtures/capability/policy.yaml` instead — every gateway accepts it, and both
  fixtures are `cmp`-verified outputs of the committed emitter — with the strict
  variant and its gateway-version precondition stated in the comment rather than
  assumed.
* The capability-spec examples in `packages/MaridIR/README.adoc` and
  `docs/deployment/PRODUCTION-GUIDE.adoc` were copy-failures: they omitted the
  mandatory profile flag and used a positional output path the parser rejects, and
  the production guide pointed at a module file that the CLI cannot evaluate. Each
  block now shows a command that runs (checked against the real CLI), including the
  Julia call `emit_capability_spec(svc; global_verbs=["GET"])`.
* The CLI warning and the emitter's `ArgumentError` named "the paired gateway fix",
  an artifact that no longer exists; both now name the upstream change
  `http-capability-gateway#112` (`c67c743`) and what an older gateway does.

* `test/interop/gateway-strict.patch` could not be applied by any git (`corrupt
  patch at ../test/interop/gateway-strict.patch:270`; four hunks declared line
  counts that did not match their bodies), which red the `Native Capability Spec`
  workflow at its "Apply paired gateway changes" step and skipped every step after
  it. The paired changes are upstream now (gateway `#112`, `c67c743`), so the patch
  is deleted rather than hand-repaired: `capability-spec.yml` pins that commit and
  asserts the strict-policy clause is present, and the deployment guide, compose
  caveat, evidence ledger and `docs/adr/0007` stop describing it as unmerged.

* Capability-spec API split left by the #1 conflict resolution (`39d250a`),
  which kept both sides of every clash. `packages/MaridIR/src/capability_spec.jl`
  was retained while `MaridIR.jl` includes only `capability.jl`, so the file was
  orphaned yet main's `Capability Spec Emission` testset still drove its
  signature; MaridIR failed on Julia 1.10 and 1.11 with
  `UndefKeywordError: keyword argument 'global_verbs' not assigned`. The orphan and that testset are
  removed (`test/capability.jl` covers the surviving emitter, 58 assertions), and
  `emit_capability_spec` now runs `validate_service` last, so a rejected route
  keeps the documented `ArgumentError` instead of degrading to a bare
  `ErrorException`.
* `scripts/bootstrap.jl` instantiates before it resolves. `Pkg.resolve()` was
  re-deriving a resolution that a committed `Manifest.toml` already states, and
  demands a usable General registry to do so; on a fresh runner depot that read
  "expected package 'Parsers [69de0a69]' to be registered" and redded MaridCodec
  and MaridTransport on both Julia versions. Resolve remains the fallback for a
  missing or stale manifest (MaridIR tracks none).
* `cli-and-emitters`, `benches/marid_bench.sh` and the `compose.yaml` policy
  mount all referenced the removed emitter: the job invoked a CLI form the parser
  rejects, against a service file the emitter cannot resolve, and grepped for
  'dsl_version: "1"' and a top-level `service:` key the surviving emitter does not
  print; the bench passed no `global_verbs` and timed a `/tmp/sample_service.jl`
  that nothing creates; the gateway container mounted
  `fixtures/capability-policy.yaml`, an output that no longer has a generator. The
  job now emits from `fixtures/capability/service.jl` and `cmp`s the golden
  policy, the bench names its verbs and times the in-repo fixture, and the
  container mounts the generated strict golden policy with the producing command
  recorded beside it.
* `docs/architecture/REPOSITORY-MAP.adoc` regenerated after `35aff92` purged the
  a2ml tree: the committed map still listed `src/bridges/`, `src/core/` and
  `verification/coverage/`, failing the estate-rules staleness step.

* Regenerated `docs/architecture/REPOSITORY-MAP.adoc` after staging: the
  generator reads tracked files, so a map generated pre-staging omits new
  paths and CI reports it stale.
* `scripts/gen-repo-map.sh`: quote-safe annotation trim. The `| xargs`
  trim interpreted quotes, so an annotation containing an apostrophe
  ("Cap'n Proto") rendered empty; `sed` trims without interpreting.
* `.machine_readable/rsr-profile.a2ml`: added the `[canon]` binding
  (2.0.4, verified against live `canon.lock`). `just repo-init` records
  the canon only in `PROVENANCE.a2ml`, but Canon lockstep reads the
  profile, so minted repos fail lockstep without this block.
* `.github/workflows/main-estate-audit.yml`: repinned cicd-suite
  `f9e173a` → `222b1d9` (main). PR#17 merged 2026-09-17 and the squash
  orphaned its head commit (NOT-ANCESTOR), failing this call and the
  governance action-pin check. Per the pin note's own instruction.
* `.github/workflows/pages.yml`: build timeout 20 → 60 min. The cold
  cabal build (casket-ssg + pandoc) exceeds 20 min and a cancelled job
  saves no cache, so the gate could never go green; warm runs take
  minutes once the first cold build completes.
