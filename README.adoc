Julia-first framework for web applications, APIs, and reactive scientific dashboards, with interoperable protocols and frontend independence.

== What this is

*Marid* is a Julia-first framework for web applications, APIs, and reactive
scientific dashboards: a small `Marid.jl` core assembling five independently
usable protocol integrations (ArangoDB, gRPC, GraphQL, Cap'n Proto, Bebop),
with a framework-independent browser client and thin React/Vue integrations —
proved by one reference application. The full product definition, scope
boundaries, contracts, and gated execution plan are the canonical
link:PROJECT_BRIEF.md[project brief]; start there.

[NOTE]
====
Status: Gate 0 (feasibility and licensing audit) not yet started. This
repository currently holds the brief, the monorepo skeleton, and the RSR
scaffolding — no Marid implementation exists yet. See
link:docs/marid-roadmap.adoc[the roadmap] and
link:docs/AFFIRMATION.adoc[the affirmation] for the honest state.
====

This repository is a *Rhodium Standard Repository (RSR)* monorepo: the Marid
program paths (`PROJECT_BRIEF.md`, `packages/`, `web/`, `contracts/`,
`fixtures/`, `examples/`, `test/`) are carried alongside machine-readable
project metadata, an AI-agent gatekeeper protocol, CI/CD, and governance
infrastructure.

== Quick start

[source,bash]
----
git clone https://github.com/hyperpolymath/marid.git
cd marid

# Check the repo satisfies the RSR shape:
just validate            # structure + metadata checks

# Read the contract before anything else:
#   PROJECT_BRIEF.md     # the product/engineering contract (§1–§9)
#   AGENTS.md              # repository instructions for coding agents
#   docs/agent-launch.adoc # the Gate 0 kickoff assignment
----

Julia and Node toolchain versions are pinned at Gate 2 alongside the CI
matrix (`PROJECT_BRIEF.md` §8–§9); until then there is nothing to
instantiate — the repository root intentionally has no `Project.toml`.

== AI-Assisted Installation

If you are an AI agent installing this project, read
link:docs/AI_INSTALLATION_GUIDE.adoc[the AI installation guide] first — it gives
the orientation order, the full prompt sequence, and the privacy notice.

The one trap worth stating up front: **do not set `RSR_NON_INTERACTIVE=1`**. It
stubs the shell builtin `read`, which also disables the loops that perform token
substitution — the run never terminates and substitutes nothing. Pipe answers to
stdin instead.

== What you get

* *The Marid program* — link:PROJECT_BRIEF.md[brief], six-package skeleton
  (`packages/`), browser-client skeleton (`web/`), contract registry
  (`contracts/`), fixtures (`fixtures/`), reference-application skeleton
  (`examples/relationship_explorer/`), and interop tests (`test/interop/`).
* *Machine-readable metadata* (`.machine_readable/descriptiles/`) — `STATE`, `META`,
  `ECOSYSTEM`, `PLAYBOOK`, `AGENTIC`, `NEUROSYM`, `CLADE`, and `anchors/ANCHOR`,
  in deed, so tools and agents can read the project's state and boundaries.
* *AI gatekeeper protocol* — `0-AI-MANIFEST.a2ml` is the universal entry point that
  tells an AI agent how to work in this repo before it touches anything, with
  per-agent instructions in `AGENTS.md`.
* *Typed ABI/FFI seam* — `src/interface/Abi/` (Idris2 type + layout proofs) over
  `src/interface/ffi/` (Zig implementation), with generated C headers. Retained
  RSR spine, required by `just validate`; it is not Marid application code.
* *CI/CD* — GitHub Actions for quality, security (CodeQL, Scorecard, secret
  scanning), multi-forge mirroring, and RSR anti-pattern enforcement.
* *Supply-chain & reproducibility* — container layering (stapeln), Guix shells,
  SBOM, and signing hooks.
* *Governance* — `GOVERNANCE.adoc`, `MAINTAINERS.adoc`, `.github/` community health
  files, and a release `AUDIT.adoc` gate.

== Repository map

The authoritative map is generated, so it cannot drift from the tree:
link:docs/architecture/REPOSITORY-MAP.adoc[docs/architecture/REPOSITORY-MAP.adoc]
(regenerate with `just repo-map`; CI fails if it is stale).

The short version:

[cols="1,3"]
|===
| Path | What lives there

| `PROJECT_BRIEF.md`, `AGENTS.md` | The Marid contract and the agent instructions — start here.
| `packages/`, `web/` | The six Julia packages and the browser client.
| `contracts/`, `fixtures/` | Contract registry and interop fixtures.
| `examples/`, `test/` | Reference application and cross-protocol tests.
| `README.adoc`, `CLAUDE.md` | This file; the generated agent arrival pack.
| `src/`, `tests/` | RSR spine seam and estate scaffolding tests.
| `docs/` | Human documentation, including the full map above.
| `.machine_readable/` | Manifests, contractiles and policies that tools read.
| `build/`, `Justfile` | Every task runs through `just`; phases live in `build/just/`.
| `ci/`, `.github/` | CI configuration; GitHub reads `.github/` and no other path.
|===
