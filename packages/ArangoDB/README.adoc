= ArangoDB.jl — Native ArangoDB HTTP Client
:toc:
:sectnums:

Standalone native Julia HTTP client for ArangoDB 3.12 (multi-model document, edge,
and graph storage). Zero dependencies on `MaridCore` (`docs/MARID-FRAMEWORK.adoc`, storage set).

Status: **In-memory prototype; NOT a verified database client.**

All operations below currently use a local dictionary, not the configured HTTP
endpoint. Transactions are stubs. Gate 3 requires a real client and pinned-container
tests; see link:../../docs/audits/evidence-ledger.adoc[the evidence ledger].

== Public API

* `ArangoClient(endpoint, database; username, password, timeout_secs)`
* `ArangoQuery(aql, bind_vars; batch_size, ttl, count)`
* `create_document(client, collection, doc; return_new)`
* `get_document(client, collection, key; rev)`
* `update_document(client, collection, key, doc; check_rev)`
* `delete_document(client, collection, key; rev)`
* `create_edge(client, collection, from_id, to_id, data)`
* `create_cursor(client, query)` & `next_batch(cursor)` & `delete_cursor(cursor)`
* `execute_aql_all(client, query)`
* `begin_transaction(client, collections)` & `commit_transaction(client, tx_id)`

== Feature Matrix

[cols="1,1,2",options="header"]
|===
| Feature | Status | Verification Evidence

| Document CRUD | Simulated only | `test/runtests.jl` verifies creation, reading, updates, and deletion.
| Revision Concurrency | Simulated only | Revision mismatch triggers `ArangoError(412, 1200)`.
| Edge Collections | Simulated only | `_from` and `_to` graph linkages verified.
| AQL Cursors & Pagination | Simulated only | Bounded batch retrieval, continuation, and cursor cleanup.
| Stream Transactions | Simulated only | Begin, commit, and abort flows tested.
|===

== Unsupported Features
* ArangoDB internal Agency consensus management (Marid does not manage database clusters).
* Foxx JavaScript microservices runtime integration.

== Environment Setup

The runnable example requires `ARANGO_USER` and `ARANGO_PASSWORD` to be set in your shell.
Export them before running Julia, for example:

[source,shell]
----
export ARANGO_USER=root
export ARANGO_PASSWORD=dev
----

These variables are read via `ENV[\"ARANGO_USER\"]` and `ENV[\"ARANGO_PASSWORD\"]` in the example below.

== Runnable Example

[source,julia]
----
using ArangoDB

client = ArangoClient("http://127.0.0.1:8529", "biomodel_test", username=ENV["ARANGO_USER"], password=ENV["ARANGO_PASSWORD"])

# 1. Create document
doc = Dict{String, Any}("binomial" => "Homo sapiens", "order" => "Primates")
res = create_document(client, "species", doc)

# 2. Query with AQL Cursor
q = ArangoQuery("FOR s IN species FILTER s.order == @order RETURN s", Dict("@order" => "Primates"))
results = execute_aql_all(client, q)
----
