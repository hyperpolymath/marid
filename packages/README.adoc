= packages — Julia packages

The thirteen Julia packages of the Marid monorepo, in framework order
(`docs/MARID-FRAMEWORK.adoc`; `PROJECT_BRIEF.md` §2–§3).

== Launch set (Phase 1)

[cols="1,3"]
|===
| Package | Role

| `MaridIR/` | Service descriptor IR: pure data plus validation. No
dependencies.
| `MaridCodec/` | Codec seam, content negotiation, JSON; MsgPack/CBOR and
Cap'n Proto/Bebop message support as extensions.
| `MaridOpenAPI/` | IR → OpenAPI 3.1 plus JSON Schema emitters.
| `MaridRPC/` | JSON-RPC 2.0 plus MCP adapter over the IR, with an SSE hook.
| `MaridGraphQL/` | IR → GraphQL SDL plus introspection first; resolver
runtime later.
|===

== Core (Phase 2)

[cols="1,3"]
|===
| Package | Role

| `MaridTransport/` | Transport seam: HTTP/1.1, SSE, WebSocket upgrade,
chunked/trailers.
| `MaridCore/` | Trie router, middleware, `CallContext`, server assembly.
|===

== Storage (Phase 3)

[cols="1,3"]
|===
| Package | Role

| `ArangoDB/` | HTTP-based ArangoDB client: auth, pooling, cursors, AQL,
transactions, retries, changefeeds.
| `MaridStorage/` | Storage seam plus SQLite/DuckDB/in-memory backends; the
Arango backend arrives as an extension.
|===

== Later (Phases 4–7)

[cols="1,3"]
|===
| Package | Role

| `MaridControl/` | Control plane: snapshot swap, log abstraction,
etcd/Consul backend (Phase 4).
| `MaridLive/` | HTMX/Turbo/Datastar helpers over SSE/WS (Phase 5).
| `MaridCRDT/` | LWW-Register, OR-Set, counters, presence (Phase 6).
| `MaridRaft/` | Own Raft — only if etcd proves insufficient (Phase 7).
|===

Status: Gate 0 skeletons throughout. Each package README names its
phase; the supersession map from the brief's original six packages is in
`docs/FRAMEWORK-ALIGNMENT.adoc`.
